Controls are stored in a library, allowing for the same control to be tested year over year without redundant details being re-entered. Also allowing results to accumulate against a stable record. The control library is categorised by business Function.

When a test references a control, the library's standard objective and tests procedures [pre-fill the test](/tests#pre-filled-from-the-control-library).

## Control fields

| Field | Type | Description |
| --- | --- | --- |
| Name | Text | The control's name. Together with Function, uniquely identifies the control. |
| Function | Picklist | The process the control belongs to (e.g. Procurement, Financial Reporting, AP). |
| Standard Objective | Rich text | What the control is meant to achieve. Pre-fills a referencing test's Test Purpose. |
| Standard Procedure | Rich text | How the control is tested. Pre-fills a referencing test's Procedure. |
| Standard Sample Size | Number | Default sample size suggested for tests of this control. |
| Frequency | Picklist | Annual / Quarterly / Monthly / Weekly / Daily / Multiple times a day. |
| Control Type | Picklist | Preventive / Detective. |
| Control Nature | Picklist | Manual / Automated. |
| Control Owner | Reference | The process owner responsible for operating the control. |
| Related Information Systems | Reference | The systems the control operates in. |

## Updating the library from a Test

While controls pre-populate the procedures and purpose of a referenced Test, Recap still allows users to adjust the fields of that specific test case while maintaining the control-reference. This allows auditors the flexibility of test-specific procedures or temporary adjustments to testing. But, auditors are also able to push the updates as the control's new canonical standard.

## Fuzzy Duplicate detection

With a large control library, it's easy to unintentionally create repeat entries (e.g. reworded names or same control described two ways). To keep the library clean, whenever a new control is entered, Recap IA compares the new entry's Name and Procedures against existing controls in the same Function using AI-based fuzzy matching.

If a likely duplicate is found, the auditor is shown the suggested existing control and chooses: use the existing entry, or override and create the new one anyway.
